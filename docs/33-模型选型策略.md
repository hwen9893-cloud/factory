# 1. center.model 多后端封装原则

`center.model` 对上层（skill/factory）暴露**统一 OpenAI 兼容接口**，底层后端可切换，呼应架构原则 ⑥ Replaceable。

```
skill → center.model（统一接口）→ ┌ 本地 Ollama / vLLM（Llama3 / Qwen ...，LLM）
                                  ├ 本地 ComfyUI（SDXL/Flux 图像、Wan/Hunyuan/LTX 视频）
                                  ├ 本地 TTS（XTTS / CosyVoice / Piper）
                                  └ 云 LLM/GPU API（可选溢出，非默认）
```

> 选型不是"一次定终身"，而是**为每类任务选最优后端，并保留切换能力**。
> **v1.1 变化（本地 CUDA 工作站）**：图像/视频（ComfyUI）与 TTS 从"云/专用"提升为**一等本地后端**，默认全本地运行；云仅在本地单卡队列积压时按需溢出（见 `32` §5/§7）。

# 2. 基座候选对比（中文爽文写作）

> 用户已指定 **Llama3** 为基座。但需正视：Llama3 系列的**中文创作能力弱于主流中文开源模型**。下表为选型依据，最终以 §3 盲测结论为准。

> 单卡 32GB 显存约束下，写作主力推荐 **14~32B 4-bit**（可与其它任务错峰常驻）；70B+ 需谨慎评估显存与错峰（见 `32` §3）。

| 模型 | 中文爽文能力 | 单卡 32GB 可行性（量化） | 备注 |
|------|------------|------------------------|------|
| **Qwen2.5 (14B/32B)** | 强（中文原生强） | 14B/32B-4bit 流畅，白天可常驻 | **中文爽文首选**，契合单卡日常主力 |
| **Llama3 / 3.1 (8B/70B)** | 中（中文偏弱，需提示工程/微调） | 8B 轻松；70B-4bit 需错峰且吃紧 | 用户指定；英文强、中文需增强 |
| **DeepSeek-V2/V3** | 强 | 体量大，单卡吃紧，追质量时短时用 | 推理/长文强 |
| **GLM-4 (9B)** | 较强 | 9B 本地轻松 | 轻量本地选项 |
| **Yi-1.5 (34B)** | 较强 | 34B-4bit 可行 | 折中选择 |

# 3. Llama3 的定位决策

采用**实测后决策**，而非拍脑袋：

1. **盲测**：用同一修仙故事种子，让 Llama3-70B 与 Qwen2.5-72B 各生成同段落，由剧情设计盲评（用 `41` 角色量化 + `72` 内容评测打分）。
2. **判定**：
   - 若 Llama3 经提示工程后**达到可用**（人工修改率 ≤ 20%，见 `22` 标准 #2）→ 保留 Llama3 为**默认写作后端**。
   - 若中文质量系统性落后 → 将 Llama3 降为**可选后端**，默认改用 Qwen2.5/DeepSeek，Llama3 保留用于英文/特定任务。
3. **中文增强（若坚持 Llama3）**：
   - 优先**提示工程 + few-shot 设定注入**（零训练成本）。
   - 次选社区中文增强权重（Llama3-Chinese 类）。
   - 继续预训/SFT 成本高，Phase 1 不做。

> 结论写回本文档 §3 并冻结；后续若换模型，只改 `center.model` 配置，不动上层 skill。

# 4. 分任务选模型

| 任务 | 推荐后端 | 部署 |
|------|---------|------|
| 小说写作 | Qwen2.5-14B/32B 或 Llama3（按 §3 实测） | 本地（白天常驻） |
| 设定审校 / QA | 同写作模型或更小的快速模型 | 本地 |
| Embedding（检索/一致性） | bge-m3 / gte 中文 embedding（1024 维，见 `61`） | 本地 |
| TTS / 配音 | XTTS / CosyVoice / Piper（多说话人），每 Character 绑定固定 speaker | 本地 |
| 图像生成 | SDXL / Flux + 角色 LoRA（ComfyUI） | 本地 |
| 视频生成 | Wan / HunyuanVideo / LTX-Video（ComfyUI） | 本地（夜间批处理，独占显存） |
| LoRA 微调 | LLaMA-Factory / PEFT | 本地（夜间/周末） |

# 5. 量化格式

| 格式 | 适用栈 | 说明 |
|------|--------|------|
| **GGUF** | Ollama / llama.cpp | 通用、量化档位丰富（Q4_K_M 等） |
| **GPTQ / AWQ** | vLLM | 追求吞吐时的 GPU 原生量化 |

> 默认 4-bit（Q4_K_M）平衡质量与显存；审校等对质量敏感的任务可上 5/8-bit（注意单卡显存与错峰）。
> 商用许可证审计：Flux-dev / XTTS / MusicGen 等部分权重为非商用，放量前需替换为可商用权重（见 `45` 合规）。

# 6. 模型评测与回归

- 每次更换模型/量化档位，跑 `72-评测工程EvalHarness.md` 的内容评测套件，与基线对比。
- 写作质量回归项：设定冲突率、人工修改率、角色量化总分分布。
- 防止"换模型导致中文质量悄悄退化"——纳入回归监控。
