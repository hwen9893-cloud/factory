# 1. 文档目的

`52-一致性技术预研方案.md` 定义了一致性的四个维度与 M3.5 验收门（"做什么 / 验什么"）。本 Playbook 回答"**在本地 RTX 5090 单卡工作站下，每个维度具体怎么落地、如何在单卡时段内错峰执行**"（"怎么做"）。

> 核心前提（见 `32`）：**LoRA 训练与视频生成本地 CUDA 可跑，改为夜间独占显存批处理**；spec 准备、prompt 组装、设定 QA 为轻量任务，与写作白天共存。全部本地，GPU 分时由队列调度器管理（`62` §10）。

# 2. 四维度落地路线（标注 GPU 时段）

| 维度 | 手段 | 执行位置（本地 GPU 时段） |
|------|------|----------|
| **身份一致（图像）** | 每角色 LoRA + canonical reference sheet（多角度定妆图） | LoRA 训练：**夜间独占**；reference 生成/试色：白天短时 `image` |
| | IP-Adapter / InstantID 类 reference-based 身份锚定 | 白天 `image` 短时 / 批量放夜间 |
| | 固定 seed 区间 + ControlNet 控姿态 | 本地 ComfyUI（CUDA 全套） |
| | 兜底：face restoration / 局部重绘 | 本地，夜间后处理 |
| **跨模态（文→图）** | appearance spec 结构化注入（发色/瞳色/服饰/标志物/体型） | **CPU/轻量（确定性注入，几乎不占 GPU）** |
| | Prompt 由 spec 确定性生成，禁止 LLM 每次重述 | 本地 LLM 组 prompt（白天常驻） |
| **时序（视频）** | 关键帧锁定 → reference 生成中间帧 | **夜间独占显存批处理** |
| | 末帧→首帧链式衔接长镜头 | 夜间 |
| | 带 reference 条件的视频模型 | 本地 ComfyUI（Wan/Hunyuan/LTX），夜间 |
| | 兜底：逐帧 face swap / restoration | 本地，夜间后处理 |
| **设定（QA）** | QA Agent 将新章节/分镜与 `center.knowledge` diff | **本地 LLM + 规则（白天，几乎不占 GPU）** |

# 3. appearance spec 字段（跨模态核心，轻量本地）

角色外观规格结构化存入 `center.asset`，由 spec **确定性注入** prompt（字段落地见 `61`）：

| 字段 | 例 |
|------|-----|
| 发色/发型 | 玄色长发束冠 |
| 瞳色 | 金瞳（异瞳设定） |
| 服饰 | 青色道袍 + 玄铁护腕 |
| 标志物 | 左眉断痕 / 古剑「噬魂」 |
| 体型/年龄感 | 清瘦少年 |
| 气质标签 | 阴冷、不羁 |

> 这是避免"LLM 措辞漂移→视觉漂移"的关键，且**几乎不占 GPU**，可与白天写作并行。

# 4. GPU 时段分配清单（单卡 32GB）

| 工具/任务 | GPU 需求 | 建议时段 |
|----------|:---:|:---:|
| appearance spec 注入 | 无 | 任意（白天） |
| 本地 LLM 组 prompt | 与写作共用 | 白天常驻 |
| 设定 QA diff | 极小 | 白天 |
| SDXL/Flux 出图 | 8~16GB | 白天短时 / 批量夜间 |
| LoRA 训练 | 16~24GB（独占） | **夜间/周末** |
| ControlNet / IP-Adapter 全链 | 含图占用 | 白天短时 / 夜间批量 |
| ArcFace 人脸 embedding 评测 | 小 | 白天可跑 |
| 视频生成 | 24~32GB（独占） | **夜间** |
| face swap / restoration 后处理 | 中 | 夜间批处理 |

> 调度由 GPU 队列调度器统一管理，独占任务（LoRA/视频）自动排到夜间窗口，见 `62` §10。

# 5. M3.5 验收门（本地工具链）

四维度基线见 `52` §4。本 Playbook 补充本地执行时段：

| 维度 | 测试 | 执行 |
|------|------|------|
| 身份一致 | 主角生成 N=20 张，ArcFace 余弦相似度 ≥ 0.6，人工判定一致率 ≥ 90% | 本地生成（夜间批量），评测脚本本地跑（见 `72`） |
| 跨模态 | 描写生成图，K 个外观属性命中率 ≥ 85% | spec 注入（轻量）+ 本地生成 |
| 时序 | 1 段 10 秒片段，帧间漂移低于阈值，人工通过率 ≥ 80% | 本地夜间视频批处理 |
| 设定 | 注入冲突测试集，QA 召回率 ≥ 80% | 本地（白天） |

---

# 6. de-scope 预案

当某维度达不到基线（尤其时序/视频，单卡产能或质量吃紧时）：

- 单维度未达标 → 在该维度迭代方案或更换技术路线，**不放行**。
- 多维度系统性未达标 → 触发 de-scope：**先做半动态分镜 / 动态漫，而非全视频**，重排 M4 范围（呼应 `21` 的有声书/动态漫优先策略）。
