# 1. 文档目的

本文档从项目管理角度，把 AI Cultivation Studio 拆成可排期、可验收、可暂停、可替换的模块化任务单元。

核心目标：

- 把 `21-精益路线.md` 的 Market-First 原则落成执行节奏。
- 把 `22-成功标准与里程碑.md` 的验收数字拆成模块任务。
- 先以 `factory.novel` 小说生产工厂作为初期框架搭建对象。
- 保持本地单卡 CUDA 工作站（RTX 5090，见 `32`）为生产中枢，重训练、视频扩散等高显存任务排到夜间独占时段。

本文不是代码实现规范；代码骨架见 `62-AgentSkills实现规范.md`，小说流水线细节见 `43-factory.novel流水线规范.md`。

# 2. 项目管理总原则

| 原则 | 执行方式 | 反模式 |
|------|----------|--------|
| 先验证后扩张 | 每个模块先做最小可运行版本，再补自动化与可视化 | 一次性搭完整平台 |
| 单模块闭环 | 每个模块必须包含输入、处理、输出、评测、人工介入点 | 只写功能，不写验收 |
| 文档即契约 | 任务启动前先确认对应文档、Schema、Prompt、评测指标 | 代码先行导致命名漂移 |
| 全本地优先 | 写文、知识库、评测、TTS、图像/视频、本地推理全部本地完成 | 过早依赖云 GPU |
| 数据可回放 | 所有运行产物必须落盘或入库，支持复跑与对比 | 只看当次生成结果 |
| 允许半手工 | Phase 1 允许脚本 + 人工审核，不强求全 LangGraph | 为自动化牺牲速度 |

# 3. 模块化任务分层

## 3.1 模块层级

| 层级 | 任务类型 | 示例 | 管理方式 |
|------|----------|------|----------|
| Program | 项目目标 | AI 内容工厂 v1 | 里程碑复盘 |
| Module | 模块 | `factory.novel`、`center.knowledge` | 模块 backlog |
| Epic | 能力包 | 小说流水线 MVP、知识库快照、QA 闭环 | 2-4 周交付 |
| Task | 具体任务 | 写 outline prompt、实现 schema 校验 | 1-3 天交付 |
| Run | 单次执行 | run_0001 生成第 1 章 | 自动记录 |

## 3.2 标准模块交付件

每个模块都必须交付以下内容：

| 交付件 | 内容 |
|--------|------|
| Scope | 模块负责什么、不负责什么 |
| Input Contract | 输入字段、引用 ID、文件或表结构 |
| Output Contract | 输出字段、产物格式、lineage 要求 |
| Prompt / Rule | Prompt 模板、规则集、人工审核标准 |
| Eval | 可复跑评测脚本或人工评审表 |
| Runbook | 如何运行、如何重试、如何回滚 |
| Handoff | 交给下游模块的文件、ID 或状态 |

# 4. 优先级策略

## 4.1 当前优先级排序

| 优先级 | 模块 | 原因 | 当前目标 |
|--------|------|------|----------|
| P0 | `factory.novel` | 内容生产的源头，最适合本地 LLM 白天验证 | 跑通小说生产工厂初期框架 |
| P0 | `center.knowledge` | 控制设定一致性，避免长篇漂移 | 先用 JSON/YAML，后接 PostgreSQL |
| P0 | `center.model` | 统一 Ollama / ComfyUI / TTS / 后续模型切换 | 固定本地模型 profile |
| P0 | `center.qa` | 承接设定冲突、Schema、合规初筛 | 先规则 + LLM 评审 |
| P1 | `factory.audio` | 有声书几乎不占视频显存，是本地友好的市场验证形式 | 小说稳定后接入 |
| P2 | `factory.visual` | 本地夜间 GPU 时段接入（图/LoRA） | 先只维护 appearance spec |
| P3 | `factory.animation` | 一致性和算力风险最高 | M3.5 之后再进入 |
| P3 | `center.operation` | 市场信号早期可用平台后台收集 | 规模化后再建设 |

## 4.2 不进入当前范围的任务

| 暂缓任务 | 暂缓原因 | 重新进入条件 |
|----------|----------|--------------|
| 70B 本地常驻 | 资源占用高，早期收益不确定 | 8B/14B 基线无法达标 |
| LoRA 训练 | 样本不足时容易固化坏模式 | ≥500 条高质量样本 + Eval 显示文风瓶颈 |
| 全量 LangGraph 编排 | 前期流程变化快 | 脚本链路连续跑通 10 章 |
| 自建运营后台 | 早期平台后台足够 | 有稳定发布节奏和多平台数据 |
| 全动画流水线 | M3.5 一致性前置未验证 | 一致性四维度达标 |

# 5. 小说生产工厂初期框架

## 5.1 初期目标

用本地工作站完成 `factory.novel` 的最小可运行生产框架：

```
story_seed
  → skill.novel.outline
  → skill.novel.plot
  → skill.novel.chapter
  → skill.novel.dialogue
  → skill.qa.consistency
  → skill.novel.export
```

`skill.novel.screenplay` 先保留接口，不作为初期硬性闭环。

## 5.2 初期不追求的目标

- 不追求全自动 Agent。
- 不追求 UI Dashboard。
- 不追求 LoRA 训练。
- 不追求多世界观通用。
- 不追求一次生成完整长篇。
- 不追求视觉或动画产物。

初期只证明：**给定一个故事种子和知识库快照，系统能稳定产出可读章节，并能发现明显设定冲突。**

# 7. 初期里程碑

## 7.1 Sprint 0：准备期（3-5 天）

| 目标 | 交付物 |
|------|--------|
| 模型可用 | Ollama + Llama 3.1 8B Instruct profile |
| Prompt 可试 | outline / chapter 两个 prompt 初版 |
| 知识可注入 | 最小 characters / realms JSON |
| 运行可记录 | `runs/run_0001/` 目录约定 |

通过标准：

- 给定一个 story seed，可生成一份 outline。
- outline 结果可落盘。
- 模型、Prompt、参数可追踪。

## 7.2 Sprint 1：单章闭环（1 周）

| 目标 | 交付物 |
|------|--------|
| 单章生产 | seed → outline → plot → chapter |
| 单章 QA | schema + 基础设定冲突检查 |
| 人工评审 | 章节人工修改表 |

通过标准：

- 能生成 1 章 1500-3000 字正文。
- JSON 产物可通过 schema。
- QA report 能列出至少 hard/soft/warn 三类问题。

## 7.3 Sprint 2：三章连续性（1 周）

| 目标 | 交付物 |
|------|--------|
| 连续生成 | 生成连续 3 章 |
| 前文衔接 | 每章注入 prev_tail 与 timeline snapshot |
| 评测汇总 | 生成 `eval_report.json` |

通过标准：

- 连续 3 章不出现硬设定冲突。
- 每章字数达标。
- 人工可读，且修改率可统计。

## 7.4 Sprint 3：十章基线（1-2 周）

| 目标 | 交付物 |
|------|--------|
| 十章基线 | 连续生成 10 章 |
| 模型对比 | Llama 3.1 8B vs 中文模型对照 |
| 决策建议 | 是否进入 audio / 是否需要 LoRA |

通过标准：

- 连续 10 章可复跑。
- Schema 合格率 100%。
- 硬设定冲突为 0。
- 人工修改率有统计，目标先控制在 ≤30%-40%。

# 8. 看板设计

## 8.1 状态列

| 状态 | 定义 |
|------|------|
| Backlog | 已识别但未排期 |
| Ready | 输入、依赖、验收标准明确 |
| Doing | 正在执行 |
| Review | 等待剧情/代码/美工审核 |
| Blocked | 外部依赖或关键决策阻塞 |
| Done | 满足 DoD，产物归档 |

## 8.2 任务卡字段

每张任务卡至少包含：

```yaml
id: NOV-D3
module: factory.novel
owner: code
reviewer: story
depends_on: [NOV-B3, NOV-D2]
input: outline.json
output: plot_ch001.json
dod:
  - 生成 3-5 张场景卡
  - 通过 plot schema
  - 写入 runs/run_xxxx/
risk: prompt 输出不稳定
status: Ready
```

# 9. 风险与处置

| 风险 | 表现 | 处置 |
|------|------|------|
| Llama 3.1 8B 中文爽文能力不足 | 文风泛、翻译腔、爽点弱 | 同步跑中文模型对照，先用 Prompt/Eval 决策 |
| 知识库过轻导致设定漂移 | 角色关系、境界、时间线乱 | Sprint 1 后立即补 knowledge snapshot |
| Prompt 变更不可追踪 | 输出质量忽高忽低 | Prompt 必须版本化，run 记录 prompt_version |
| 过早工程化 | 花大量时间搭平台，内容产出慢 | Phase 1 允许脚本链路，不强制 Dashboard |
| 样本不足就训练 | LoRA 过拟合，质量不升反降 | 先积累 gold sample 和 Eval，训练后置 |
| QA 只靠 LLM | 漏检硬设定冲突 | 规则检查优先，LLM QA 补充语义问题 |

# 10. 阶段退出条件

小说生产工厂初期框架完成后，必须产出一页《模块决策报告》：

| 决策项 | 可能结论 |
|--------|----------|
| 模型选择 | Llama 3.1 8B 继续 / 切中文模型 / 云端 fallback |
| 自动化程度 | 继续脚本链路 / 引入 LangGraph |
| 下个模块 | `factory.audio` / 强化 `center.knowledge` / 扩展 `screenplay` |
| 训练决策 | 暂不训练 / 准备 LoRA 数据 / 本地夜间 LoRA 实验 |
| 市场测试 | 有声书试投 / 纯文本连载试投 / 继续内部打磨 |

进入下一阶段的最低条件：

- `factory.novel` 可连续生成 10 章。
- 所有产物有 run 记录。
- Schema 合格率 100%。
- 硬设定冲突为 0。
- 人工修改率有稳定统计。
- 至少完成一次模型或 Prompt A/B 对比。

# 11. 一句话总结

当前项目的第一块积木不是完整平台，而是一个可复跑、可评测、可人工接管的 `factory.novel` 初期框架。只要小说生产工厂能在本地工作站上稳定生成、校验、归档和复盘，后续的音频、视觉、训练和运营才有可靠的上游输入。
