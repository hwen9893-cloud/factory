> Version：v1.0　Last Update：2026-07

> 依赖：`docs/21-精益路线.md`（Phase 0）、`docs/32-硬件与部署方案.md`、`docs/45-合规与内容安全.md`、`docs/72-评测工程EvalHarness.md`

# 0. 核心判断

按 `docs/21` 的 Market-First 内核，**Phase 0 本来就不依赖本地重硬件**——写作/TTS/验证都能用现成工具（网页 LLM + 云 TTS + CapCut）先跑。所以这两周不是空窗，而是：

1. **产内容 + 验证市场**（不需要新机器，最高杠杆）；
2. **为本地 CUDA 工作站落地做好一切软件准备**（装机当天即可开跑）；
3. **完成硬件切换带来的文档收尾与选型预研**。

> 目标：机器一插电，就已经有「锁定的 IP + 一批角色卡 + 3–5 章稿 + 一条已发布试片 + 评测脚本 + 仓库骨架 + 部署脚本」在手，直接进 Phase 1。

# 3. 装机到手第一天的动作（前置已就绪）

机器到位后，因软件准备已完成，可当天完成冷启动：

1. 跑 `docs/32` §10 到手核对命令，实物对齐配置单（重点验 5090 真卡、内存扩容到位）。
2. 满载 30 分钟压测（温度/降频/噪音）。
3. 执行 C4 部署脚本一键拉起：Ollama/vLLM + ComfyUI + PG/pgvector + Redis/Celery。
4. 跑 C2 模型盲测：Qwen2.5-32B vs Llama3，冻结写作默认后端（写回 `33` §3）。
5. 导入 A 轨知识库与稿件，跑 C1 评测脚本建立基线。
6. 建异地备份（知识库 + 案例库），验证 C6 恢复脚本。
